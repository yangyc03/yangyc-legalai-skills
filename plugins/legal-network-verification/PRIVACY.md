# 个人信息处理与授权提示

## 用户责任

使用者应自行确认对查询对象开展网络核查、使用相关个人信息具有合法依据并已取得必要授权。本提示不替代使用者依法履行的告知、同意、委托、保密或其他义务。

## 完整身份证号码

- 不得在对话中发送完整身份证号码，也不得将其交由 Agent 或 Skill 读取。
- 旧式15位和现行18位身份证号码均属于完整身份证号码，适用相同的禁止规则。
- 目标网站确有必要时，号码必须由用户在网页中手工输入和提交。
- Agent 或 Skill 不得把完整号码写入 JSON、Markdown、DOCX、日志、文件名、截图、水印或图片元数据。用户在全部技术检查完成后自行补填的归档 DOCX 属于下文所述人工例外；自补填时起，该文件立即退出本 Skill 的处理范围。
- `masked_id_number` 如已存在，只能保留前10位并将末8位替换为星号，例如 `1101011990********`；它不能替代正式记录的完整身份证号码人工填写位置。

## 敏感查询前的确认

任何 Agent 在需要用户使用完整身份证号码前，必须暂停并取得以下明确确认：

> 我确认有权在本次查询中使用该查询对象的身份证号码；完整号码由我本人在目标网页中输入并提交，不发送至对话，不由 Agent 或 Skill 保存、读取或上传；查询结束后清除输入并删除未脱敏临时材料；由 Agent 或 Skill 留存、读取或继续处理的成果仅显示末8位遮挡的身份证号码。正式记录确需完整号码的，我只在全部技术检查完成后自行补填，并不再将补填版交给 Agent 或 Skill。

该确认只适用于当前任务中的特定查询对象和特定网站。更换对象或网站后应重新确认。

## 登录、验证和截图

- Agent 可在授权范围内继续使用用户已登录的会话，但不得读取、导出或保存 Cookie、密码、Token 和浏览器凭证。
- 浏览器自动填入账号或密码时，Agent 仍不得读取字段、点击登录按钮或按回车提交；密码管理器选择、Touch ID、MFA 和登录提交均由用户完成。
- 短信验证码、滑块、人脸验证及其他安全挑战均由用户完成。
- 人工接管期间 Agent 不读取页面、不截图、不点击、不输入、不轮询；用户回复固定恢复语后，仍须确认同一浏览器、域名和范围项且敏感界面已消失。
- 用户提交查询后，只有在确认结果页面不显示完整号码时，Agent 才能恢复操作和截图；提交后会话失效或验证挑战使提交状态不明时不得自动重提。
- 页面仍显示完整号码时，禁止 Agent 截图。用户可先在本地制作脱敏副本，或记录“因敏感信息保护未留存该页面截图”。

## 结束和清理

任务结束前，Agent 应提示用户确认已清空输入、退出或关闭敏感页面，并删除未脱敏临时文件；随后运行成果扫描。

Skill 只能检查和清理其控制的临时文件和输出，不能承诺删除目标网站记录、浏览器历史或缓存、操作系统缓存以及第三方服务日志。

## 对外文件和归档补填

正式记录默认以 `user_fill` 在第三列显示 `【待用户填写】`（草稿）或保留为空（final）。公司仅在用户明确选择 `auto_fill_company_credit_code` 后，才可自动填写已验证的统一社会信用代码；自然人不得自动填入任何身份号码。

Skill 只生成不含完整身份证号码的正式记录。监管或其他正式文件确需完整身份证号码的，用户只能在 Skill 完成成果审计、结构检查和逐页渲染后自行补填。补填后的归档文件不属于 Skill 可访问或控制的成果，不得再次交给本 Skill 读取、渲染、截图、审计或复核；Skill 也不得声称已验证补填内容或归档版。
