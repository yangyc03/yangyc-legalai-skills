# 已登录浏览器与人工接管恢复规则

## 适用范围

本规则用于已确认 `query_scope` 内的公开网站查询。可以复用用户浏览器中已经存在的登录态，但不得读取、选择、复制、记录或自动提交浏览器保存的密码，也不得检查 Cookie、Token、浏览器 Profile、localStorage、sessionStorage 或密码管理器。

密码管理器选择、密码自动填充确认、Touch ID、MFA、短信验证码、图形验证码、二维码、滑块、人脸验证及登录提交全部由用户本人完成。即使浏览器已经自动填入账号或密码，Agent 也必须停止，不得读取字段、点击登录按钮或按回车提交。

## 查询前锁定

在访问页面前锁定并记录：

- `scope_item_id`、主体、查询事项和查询条件；
- 允许域名及目标网站；
- 浏览器表面和选择方式；
- 提交前的安全恢复位置，只保存 `scheme + host + path`，去除查询参数和片段。

用户明确指定浏览器时，只能使用该浏览器，不得切换。用户未指定时，可以自动选择一个已连接浏览器；在首次提交前，最多尝试一次其他已连接浏览器。切换后仍须保持同一主体、同一网站域名和同一范围项，并将选择方式记为自动回退。进入人工接管后不得再切换。

## 页面级访问探测

只检查当前网页可见的页面级状态，不探测浏览器或账号内部状态：

1. 查询界面和所需控件可用时，进入 `ready`。
2. 出现登录入口、登录表单、登录重定向、会话过期提示或查询控件因登录而不可用时，进入人工接管。
3. 出现验证码、短信、二维码、滑块、人脸或其他人工验证时，进入人工接管。
4. 出现 403、429、付费权限、网站维护、网络错误或工具错误时，如实记录相应阻断，不得推定零结果。

站点配置中的文字、路径和界面线索均为启发式信号；必须结合当次页面确认。页面布局或语义不明确时失败关闭。

## 查询控件遮挡门

在提交查询前，对拟点击控件执行一次只读命中检查：确认控件中心点最上层元素仍是该控件或其可交互子元素。若最上层元素属于浮动导航、广告、悬浮服务或其他链接：

1. 不执行该次点击，也不改用相同坐标的低层级点击；
2. 不把误跳页面记为查询已经提交；
3. 优先使用键盘提交，但只有页面当次确实绑定且提交后进入正确结果页时才接受；
4. 键盘路径不可用时，仅可使用 `site-profiles.md` 中当次重新核验的同域官方查询契约，执行一次带已确认查询条件的直接导航；不得猜测路径、参数或批量尝试候选网址；
5. 直接导航进入结果页视为一次查询提交。出现验证码、会话挑战、网络错误或页面状态不明时，继续适用人工接管或 `submit_state=unknown` 规则。

浏览器实时查询地址可以临时包含查询参数；schema 1.2 只保存去除查询参数和片段后的同域规范结果页位置，查询条件保存在结构化字段中。不得把带主体名称、统一社会信用代码、验证码或其他条件的完整实时地址写入运行文件、成果或治理记录。

## 人工接管

识别到登录、会话过期或人工验证后，立即：

1. 将 `execution_state` 记为 `pending_user_action`，并写入相应 `access_state` 和 `block_reason`。
2. 如实告知用户：“本网站尚未完成核查，不是零结果。”同时说明需要用户操作的浏览器、网站域名和范围项。
3. 暂停该页面的一切读取、DOM/辅助功能树检查、截图、点击、键盘输入、轮询和自动刷新。
4. 不保存登录页、密码页、验证码页、二维码页或全应用截图；不把这些页面作为查询证据。
5. 等待用户本人完成密码管理器选择、登录提交、Touch ID、MFA 或验证挑战。

接管期间不得用网页搜索、其他工具或另一个浏览器绕过暂停。只有用户发送完全一致的恢复语：

```text
已登录，可以继续
```

才允许恢复。其他含糊回复不视为完成。

## 恢复探测

收到固定恢复语后，只执行最小恢复检查：

1. 确认仍为锁定的浏览器表面、允许域名和 `scope_item_id`；
2. 确认登录或验证界面已消失，查询界面可用；
3. 确认当前页面没有可见密码、验证码、二维码或完整身份证号码；
4. 只有上述检查全部通过，才在 `attempts[]` 记录 `resume_safety_check_passed`，再从同一范围项继续；固定恢复语本身不能代替该检查。

任一条件不满足时再次进入 `pending_user_action` 或记录终态阻断，不自行扩大范围。用户只表示“已经登录”不能证明查询完成，也不能支持 `no_match_displayed`。

## 提交后的挑战与重提

- 提交前发生登录或验证挑战时，`submit_state=not_submitted`。
- 查询提交后发生会话过期、验证挑战、网络错误、工具错误或页面状态不明时，必须使用 `submit_state=unknown`，停止自动操作，不得自动重复提交。
- 重新提交须向用户说明范围项及重复提交风险，并取得针对该次重提的明确确认；确认不扩展到其他主体、网站或范围项。
- `submit_state=unknown` 未解决前不得生成最终 DOCX，也不得记录 `no_match_displayed`。

## 用户停止与终态转换

用户可以明确决定停止某一范围项。收到明确决定后，才可将该项由 `pending_user_action` 转为终态 `blocked`，使用 `block_reason=user_stopped`，并以 `access_limited` 如实记录“未完成查询”。不得把用户暂未回复、登录失败或验证未完成自行视为用户停止。

## 与用户手工敏感输入的关系

登录接管不构成使用完整身份证号码的授权。网站确需完整号码时，另行读取 `privacy-and-sensitive-query.md`，按特定对象和特定网站取得确认，并由用户本人手工输入和提交。出现登录、会话过期、验证挑战、页面变化、浏览器切换或操作中断后，如仍需完整号码查询，必须重新确认当前对象、网站和安全页面状态。

## 证据边界

- 普通页面证据只能是恢复后取得的网页区域水印截图；Computer Use 或系统级全应用截图不能作为证据。结果页仍显示完整身份证号码时，按 `privacy-and-sensitive-query.md` 使用 `not_retained_sensitive_page` 例外，由用户或律师目视复核，不读取或截图该页面。
- 登录、验证和接管过程不留页面截图，也不进入运行文件原文。
- 保存的安全恢复位置不得含账号、查询参数、身份证号码、Session ID 或其他凭证。
- `attempts[]` 只记录顺序号、时间和状态码，不记录页面正文、账号、Profile 名或原始工具响应。
