# Security Policy

## Supported versions

Only the latest release of each public plugin is actively maintained unless its release notes state otherwise.

## Reporting a security issue

Do not disclose secrets, client information, personal data, case materials, or exploitable details in a public Issue or Pull Request.

Use GitHub's private vulnerability reporting feature when it is available. If private reporting is unavailable, contact the maintainer through the public contact method listed on the [yangyc03 GitHub profile](https://github.com/yangyc03) without including sensitive content in the initial message.

If a credential has already been exposed, revoke or rotate it immediately before attempting repository cleanup.

## Public repository boundary

The repository must not contain:

- API keys, tokens, passwords, credentials, or `.env` files;
- client names, project names, case facts, workpapers, or deliverables;
- private templates, firm-only branding, account information, or signatures;
- machine-specific absolute paths, caches, logs, or runtime state;
- third-party material without a clear right to redistribute it.
