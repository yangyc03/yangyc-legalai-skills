# 聊天录屏工具 2.2.0

这是一个仅限 macOS 的本地工具，用于处理用户有权使用的微信聊天录屏。本公开版本不附带视频、聊天记录、语音模型、密钥或任何运行日志；处理前请确认您对视频和其中个人信息具有合法处理权限。

仓库中的可运行源码位于 [`src/`](src/)；GitHub Release 中的 macOS 安装包已将 `src/` 内文件放在压缩包顶层，可直接按下文双击使用。

把微信聊天记录滚动录屏整理为连续截图、可打印 PDF 和可检索 Word 文字稿。2.2 增加直接 Word 输出、文件夹批量处理、案件级成员映射及可选“录制人补充说明”。微信语音仍只有在画面气泡、播放时间和音频片段相互印证时才会写入聊天正文。

## 文字稿样式

```markdown
- **张三** [00:03:12] 【语音转写】这个付款节点还需要再确认一下。
- **李四** [00:03:28] 好的，我下午核对。
- **张三** [00:04:06] 【语音转写·待核】合同金额好像还需要调整。
- **李四** [00:04:35] 【语音·未能转写】
```

文字稿首部会先显示聊天类型、双方身份或微信群名称，再列出录屏中打开的微信群信息、聊天信息或联系人资料页；不会摘录微信号等资料字段。群聊按每条左侧气泡上方的微信显示昵称分别标注，未能充分确认的昵称加 `⚠`；工具不会把微信昵称擅自推定为实名。Markdown、语音匹配依据、播放区间和内部识别数据均保存于隐藏的 `.内部数据/`，不作为交付成果显示。

## 首次检查和准备

每台 Mac 都要单独双击一次：

```text
安装或修复运行环境.command
```

它会：

- 在 `~/Library/Application Support/聊天录屏工具/` 建立本机运行环境；
- 安装缺失的 Python 运行依赖和 `ffmpeg`；
- 检查 macOS Vision 和已安装的 Tesseract OCR；
- 优先复用 MacWhisper 已下载的本地模型，不自动下载新的语音模型。

模型、虚拟环境、API 密钥都不保存在项目目录，不进入 OneDrive 或 Git。MacWhisper 使用其本机加速；whisper.cpp 在 Apple Silicon 使用 Metal，Intel Mac 使用 CPU。

只有在本机没有可调用的 MacWhisper 本地模型、也没有现成 GGML 模型时，才需要考虑备用模型。下载必须由用户显式传入 `small` 或 `medium`：

```bash
bash "安装或修复运行环境.command" small
bash "安装或修复运行环境.command" medium
```

`small` 约 488 MB，`medium` 约 1.53 GB。不传参数时绝不下载语音模型。

## 使用

双击 `处理视频.command`，把视频拖入窗口。首次处理建议先做预检，确认左右对话人和群聊成员。

命令行示例：

```bash
APP="$HOME/Library/Application Support/聊天录屏工具"
"$APP/venv/bin/python3" video2screens.py 聊天录屏.mp4
"$APP/venv/bin/python3" video2screens.py 聊天录屏.mp4 --preview
"$APP/venv/bin/python3" video2screens.py 聊天录屏.mp4 --start 10 --end 300
```

语音高级参数：

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `--voice auto\|off` | `auto` | 自动尝试本地语音识别，或关闭 |
| `--asr-model small\|medium` | `small` | MacWhisper 不可用时，选择已安装的 whisper.cpp 备用模型 |
| `--audio-track auto\|编号` | `auto` | 多音轨时指定 ffprobe 音轨编号 |
| `--keep-voice-audio` | 关 | 仅排查问题时保留轻度降噪的核对音频 |
| `--narrator auto\|off` | `off` | 可选：转写非微信语音播放时段的环境人声，作为录制人补充说明 |
| `--narrator-name 姓名` | 空 | 可选录制人姓名；未填写时只显示“录制人补充说明” |

本机配置在 `~/Library/Application Support/聊天录屏工具/工具配置.json`，格式参考 `工具配置.example.json`。命令行显式参数优先于本机配置。

## 语音与噪声处理边界

- 自动顺序是：MacWhisper 已安装本地模型 → 现有 whisper.cpp GGML 模型 → 明确报告缺口。
- MacWhisper 只允许 `whisperkit:` 或 `whisper-cpp:` 本地模型，不传 `--persist`，不写入转写历史。
- 系统声和麦克风分轨时，优先选系统声并排除麦克风轨。
- 只有混合音轨时，只关联声音发生时画面中可见的语音气泡，并进行适度降噪。
- 没有气泡画面依据的麦克风说话、通知声或其他应用声音不写入文字稿。
- 通知声或环境人声与语音消息在单一音轨中完全重叠时，无法保证彻底分离；工具会降级为“待核”。
- 语音气泡存在但录屏中没有播放时，输出 `【语音·未能转写】`。

### 录制人补充说明（默认关闭）

如录屏中包含录制人的背景说明，可显式使用 `--narrator auto`。工具会排除已定位的微信语音播放区间，把其余识别到的人声按时间放入相邻聊天段落之后：

```markdown
- 【录制人补充说明】这是后续租金谈判的背景说明。
- 【张三补充说明】……
```

- 未指定 `--narrator-name` 或 `视频信息.json` 的 `narrator_name` 时，绝不固定或猜测姓名。
- 它不是微信聊天消息；声音质量偏低时显示为 `【录制人补充说明·待核】`。
- 单一混合音轨不能可靠区分录制人、其他应用和环境声，因此开启后仍应人工核对。

## OCR 选择

- 默认使用 macOS Vision 识别中文聊天画面。
- 只对文字过少、未识别或疑似乱码的画面调用本机 Tesseract，再逐帧择优。
- 选择结果保存在隐藏的 `.内部数据/ocr_engine_events.jsonl`；不下载新的 OCR 模型。
- Docling 专用 RapidOCR 模型暂不接入，避免为聊天截图引入过重依赖。

## 成果和安全性

```text
<视频名>_截图/
├── 01_截图/
├── 02_可打印PDF/聊天记录（可打印）.pdf
└── 03_文字稿/聊天记录.docx
```

- 默认只显示以上三类成果。为支持“不重跑视频即可改名并重新生成文字稿”，内部 Markdown、OCR、页面与语音定位记录、预检信息保存在隐藏的 `.内部数据/`；不需要查看或交付。
- 原视频只读，不被改写。
- 视频先完成解码、音轨和运行环境预检，不再事先删除旧成果。
- `01_截图`保留全部有效稳定页面，并在筛选后连续编号为 `0001.png、0002.png…`；可打印 PDF 根据新增内容量适度精简，但微信群信息、聊天信息和联系人资料页强制保留。
- 横向切换的动画中间帧不会进入正式截图、PDF或文字稿；筛选依据写入 `page_events.jsonl`。
- 新成果在同目录临时生成，完成后才发布；旧成果改名为 `_上次结果_时间`保留；中断时会清理本次临时目录。
- OCR 或语音处理失败时，内部状态明确标记“不完整”，不沿用旧文字稿。
- 默认 OCR 和语音转写全部本地运行。只有用户主动启用 `--attrib-llm` 时，群聊消息文本才可能发送到用户配置的 OpenAI 兼容接口；该功能默认关闭，API Key 只从本次命令行或 `LLM_API_KEY` 环境变量读取。

## 批量处理与案件级成员表

双击 `批量处理视频.command`，把包含视频的文件夹拖入窗口。工具将逐段生成独立成果，并在 `聊天录屏工具批量成果/汇总/` 中复制每段的 PDF 与 Word 文稿。

首次批量运行会生成 `聊天录屏工具批量成果/成员名单.json`。填写已确认的右侧/左侧姓名、群名和 `members` 昵称映射后重新运行，可在所有视频中共用这些已确认的信息。未知头像成员仍在各段视频内独立编号，工具不会跨视频自动认定为同一人。

## 修改人名并重新生成 Word 文稿

预检阶段可在 `视频信息.json` 填写一对一双方姓名，或填写“微信显示昵称 → 实名”对应关系。完成后如需改名，可重新生成文字稿；已有语音结果从内部数据读取，不重新提取音频：

```bash
APP="$HOME/Library/Application Support/聊天录屏工具"
"$APP/venv/bin/python3" regenerate_md.py <成果目录> --me 张三 --other 李四
```

不想使用命令行时，直接双击 `修改人名并重新生成文字稿.command`：

- 一对一聊天：依次填写右侧、左侧姓名；
- 群聊：可一次填写多组 `微信昵称=实名`，例如 `Lily=张三；小王=王五`；
- 对于画面中没有读到昵称的群消息，工具会按头像和画面位置合并为“未识别成员1、未识别成员2…”。入口会列出每组的消息数量和少量文字样本，可填写 `1=张三；2=李四`，该成员组的全部消息都会一起更新；
- 只有无法归入任何成员组的极少数消息，入口才会逐条列出并允许按序号补充指定；
- 也可填写“录制人姓名”；未填写时说明统一显示为“录制人补充说明”。
- 只会更新 Word 文字稿，不会重新读取视频、重做截图或转写语音。

## 测试

```bash
python3 -m unittest discover -s tests -p 'test_voice_pipeline.py' -v
python3 tests/test_pipeline_legacy.py
```

语音引擎优先使用本机 MacWhisper 本地模型，[whisper.cpp](https://github.com/ggml-org/whisper.cpp) 仅作兼容备用。

## 适用范围与人工复核

- 本工具只整理用户有权处理的录屏，不替代对聊天真实性、完整性、身份归属或证据效力的人工判断。
- OCR 和转写可能出错；带 `⚠` 或“待核”的内容必须回看原视频核对。
- 不适用于绕过平台权限、提取他人账号数据，或将未经授权的聊天内容上传、公开或作为唯一证据依据。
